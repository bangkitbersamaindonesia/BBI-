# SO → PO → bills → invoice → returns

Sales enters shop/customer, product SKU/name and quantity (canonical pcs), with salesperson, delivery address/date and unit sale price. Submitting SO now atomically checks free stock in Lebak → Kediri → Besar, reserves stock, and creates one automatic draft PO for shortages only. Fully stocked orders create no PO. Supplier is left blank for Admin 1 to choose, not guessed from SKU.

Admin 1 uses Purchasing to set supplier and destination warehouse, add/remove SKU rows and adjust qty/prices before saving. Authorization requires a supplier; only an authorized PO can be downloaded/printed. Authorized PO cannot be edited in place. Draft changes retain before/after history. PO dispatch remains manual. Current demo supports one PO/supplier per SO; split sourcing and partial/backorder cycles are not implemented.

Admin 1 records final vendor bills: each PO SKU defaults to zero, fill only supplied quantities. Missing/short quantities linked to customer demand become loss sales; extra procurement not ordered by the customer never becomes lost customer demand. Received purchases beyond demand remain free warehouse stock. Bills alone do not assert physical arrival: Admin 1 confirms goods received before stock increases, valuation updates and relevant SO reservations are added. Duplicate receipt is blocked.

After supplier final response and receipt, Admin 1 prepares final customer shipment/invoice from SO and available reservations. Remove SKU by setting shipment qty to zero (button provides reason), add catalog SKUs from free stock, or use the existing approved substitute flow. Added/replacement products require customer confirmation. Invoice creation and stock reduction commit together exactly once. Insufficient stock/invalid qty leaves state unchanged. Final unsent demand becomes loss without duplicating supplier loss. Source SO is retained; created invoice/shipment is immutable. Corrections after creation use returns, not silent line edits.

Customer returns: Sales submits linked invoice lines; Admin 2 chooses receiving warehouse and confirms physical receipt. Approval appends inventory receipt and customer credit, reducing invoice balance and reversing original HPP. Supplier returns: Admin 1 confirms goods returned from free stock; approval reduces stock and bill balance. Original invoices/bills remain unchanged. Existing return tests cover duplicate approval, entitlement limits, roles and atomic failures.

All records, simulated role controls and stock changes remain page-session demo data. Reload resets them. No database, authentication, vendor transmission, production ledger or payment integration. Invoice preview discount/tax/letterhead settings remain preview-only; workflow financial totals are merchandise values before preview taxes and discounts.
